# 共享研究库与编号目录

## 目标

以全局共享的来源、证据、指标与因子为核心。主题是引用这些对象的研究视角，处理批次只记录加工过程，不划分知识所有权。同一原始依据被多次引用不构成多份独立证据。

## 编号目录

| 目录 | 职责 |
|---|---|
| `00-guide/` | 设计、流程和迁移说明 |
| `01-inbox/` | 待接收资料和处理结果包 |
| `02-sources/` | 不可覆盖的来源，内容主题 → 类型 → 来源 → 版本 |
| `03-library/` | 跨主题共享研究库，人可读入口及对象关系 |
| `04-research/` | 研究问题视图、待核验事项和历史报告阅读副本 |
| `05-runs/` | 不可修改的历史运行快照 |
| `06-reviews/` | 不可修改的历史复盘 |
| `07-exports/` | 对外导出物 |
| `90-system/` | 脚本、数据契约、运行数据库、配置、测试和提示词 |

README.md 只保存目录职责、使用方法和导航，不承载真实研究数据，也不被数据刷新覆盖。实际对象分别输出到 sources.md、evidence.md、metrics.md、factors.md、hypotheses.md；数据统计输出到 overview.md。数据页默认用 Markdown 总表、字段表、使用记录表和关系表呈现；机器 ID 折叠显示，JSON 仍是后台结构化数据。

共享库内 `01-sources`、`02-evidence`、`03-metrics`、`04-factors`、`05-relations` 是可再生阅读视图；`06-catalog` 保存导入索引，`07-models` 保存版本化模型，`08-packages` 保存不可覆盖的规范化结果包。

## 对象与版本

增加共享对象、定义版本、批次使用关系、对象关系四类表。历史批次表不改写：它们记录当时的提取和判断；共享对象层将其关联起来。指标定义与期间、数值分开；因子定义与方向、置信度、证据和评估时点分开。

默认只合并定义完全一致的对象，使用定义内容哈希生成共享 ID，不凭名字相似合并。结果包可为指标和因子填写 `shared_id`，显式沿用身份；单位、口径、机制等变更形成新定义版本。相同 shared_id 不同对象类型必须拒绝。相同定义但不同 ID 的语义归并需要人工决定。

证据身份由来源快照内容、摘录、定位和说法共同决定；同一证据的 pending/verified 等审核记录留在不同使用记录中，不以最新状态覆盖历史。来源类对象沿用来源 ID；来源版本以文件内容和来源身份标识，元数据另保留在批次中。

关系包含指标依据、因子使用指标、因子引用证据、因果假设引用证据。引用只表示被使用，不自动表示支持或因果成立。支持/反驳关系通过独立的版本化关系文件登记，必须引用实际证据版本和因子/假设版本、填写解释及审核状态。多主题能引用同一对象；同源支持不能当作独立重复验证。

## 历史兼容

迁移只移动正式来源、结果包、导入索引、历史运行和复盘文件，不修改其内容或数据库中冻结的旧路径。CLI 用明确的旧路径映射解析现存位置。历史 Markdown 保留原样；`04-research/02-history/` 提供重新解析路径的阅读副本。原报告内旧链接以历史记录为准，不是当前导航入口。

共享阅读视图由已验证完整性的结果包重建，不手工编辑。修改对象应生成新结果包；修改支持/反驳关系应新增关系文件；不能直接改生成的 Markdown。SQLite 为查询载体，包、关系文件和原始资料保留可重建依据。
