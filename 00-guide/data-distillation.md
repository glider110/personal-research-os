# 数据蒸馏：数据源 → 指标 → 因子

当前阶段只完成资料提取、核对、整理和因子提炼。停止在默认流程中生成因果链、情景、行为树和投资判断。旧运行保留作历史记录。

## 三层定义

| 层 | 解决的问题 | 产物 |
|---|---|---|
| 数据源 | 信息从哪里来，原文是什么？ | 来源目录与原始文件 |
| 指标 | 与主题有关的哪些数据值得留下？ | 每个指标的多维特征表、历次观测表 |
| 因子 | 多个指标背后，哪些是尽量不重复的底层因素？ | 少量候选因子、代表指标、提炼理由和独立性说明 |

因子是从指标中抽出的核心解释维度。例如融资总量和融资结构都可能描述资金可得性；不能因为有五个相似指标，就算五个独立因素。“秩、线性无关”是去冗余的类比；目前没有足够同口径时间序列做统计验证，不标注正交、独立性已证实或自动计算权重。

## 一个指标，两张表

特征表：名称、单位、范围、统计口径、主题相关性、数据真实性/核对状态、来源、领先/同步/滞后属性及参照对象、大众/小众属性及判断依据、旁证指标及对应说法、反证指标及对应说法、频率。

观测表：统计起止时间、数值、单位、原始发布日期、采集时间、原文定位、核对状态。每期数据单独保留；相同来源相同观测跨批次不重复显示，不同来源或修订值保留。累计值不能当单月值；没有多期数据也不伪造时间序列。

核对状态只说明摘录/数值是否与原文一致，不保证源头统计绝对真实。官方来源、核对状态、采集完整度分开显示。大众/小众与领先/滞后属于带理由的分析标注，可填未知。旁证与反证是相对于具体命题的关系，必须引用真实指标；尚未采集的指标记入缺口，不伪装成已获得的数据。

## 指标到因子的过滤

先核对真实性，再去重，再交叉验证。未核对数值不能作为因子依据；相同信息组、相同期间的原始量与同比等衍生表达，只选一个代表，其余说明排除理由。排除是退出因子计数，原始指标仍保留备查。

因子表直接列：代表指标、旁证/反证/口径对照、排除指标与原因、逻辑核验结论。反证不能隐藏，同源数据不能冒充独立证明。只有一个代理指标或缺少独立旁证时明确写“交叉验证不足”，因子保持候选。

`features.information_group` 标记同一底层测量的信息组，`representation` 标记原始量/变化率/综合指标。未标注时不自动猜测衍生关系。因子的 `cross_checks` 和 `excluded_metrics` 保存核验与排除理由；`validation_note` 保存逻辑核验结论。旧包缺这些字段时显示尚未完成过滤。

## 因子表

每个因子写清名称、底层含义、所依据指标、提炼/去重理由、与其他因子可能重叠之处。允许只有指标没有因子，证据不足不强行提炼。当前因子均为候选解释，不生成情景、预测或投资动作。

## 当前入口和操作

阅读 [房地产数据蒸馏](../04-research/real-estate.md)，再按需打开 [指标库](../03-library/metrics.md) 和 [因子库](../03-library/factors.md)。来源按内容→文件类型保存，指标和因子跨主题共享。

Agent / NotebookLM 先提取，再按 `distillation-package.schema.json` 生成 schema_version 为 `2.0` 的数据蒸馏包。证据摘录留在包内作为核对依据，不要求用户单独维护一层证据关系图。

```bash
python3 90-system/scripts/research.py distill <package.json>
```

这一条命令校验、导入并刷新三层阅读页。它不运行情景推演。原有 validate/import/library 仍可分步使用。资料更新创建新包 ID；原文件、已导入包和历史运行不可覆盖。尚未实现全格式自动解析，提取内容由 Agent 或人工核对后输入。

已导入旧版 1.0/1.1 包继续可读；新导入只接受 2.0 包，旧因果设计与执行器已删除。

## 精简后的目录

`01-inbox/` 接收资料，`02-sources/` 保存原件，`03-library/` 只放来源表、指标表、因子表，`04-research/` 放主题入口与待核对项。`00-guide/` 只保留当前规范和来源规则。代码、契约、结果包、索引、核对记录统一收进 `90-system/`。

废弃的因果模型、执行器、情景模板、重复指南和空导出目录删除。真实历史快照集中到 `90-system/history/`，不保留第二套阅读副本。原件与已导入包内容不改写；旧存储路径由路径映射解析。
